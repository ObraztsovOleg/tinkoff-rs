# Стратегия «ИИ-модель»

`kind = "ai-model"` — стратегия, в которой торговое решение принимает внешняя
ИИ-модель. Перед открытием каждой торговой сессии модель читает свежие новости,
сама запрашивает нужные ей свечи, индикаторы и мультипликаторы и выбирает доли
капитала для инструментов своего блока. Стратегия работает как остальные: её
можно поставить в портфель отдельно, в комбинацию с другими стратегиями или
перевести после проверки в Sandbox на реальный счёт.

> Модель может ошибаться и не гарантирует прибыли. Новостные тексты могут быть
> неточными или содержать манипуляции. Лимиты ниже ограничивают ущерб, но не
> делают решения модели надёжными. Проверяйте стратегию в Sandbox.

## Подключение модели

Подключение задаётся в файле профилей — **провайдер, адрес, модель и токен**.
В Compose это `docker/local/ai/models.toml` (не в Git, права 0600; создаётся из
`examples/ai-models.example.toml` командой `python3 scripts/compose-setup.py init`).
Без Compose путь задаёт переменная `AI_MODELS_FILE`.

```toml
default = "claude"

[models.claude]
provider = "anthropic"                 # Anthropic Messages API
url = "https://api.anthropic.com/v1"
model = "claude-opus-5-5"
token = "..."                          # или token_env = "ANTHROPIC_API_KEY"
web_search = true                      # поиск в интернете на стороне Anthropic

[models.local]
provider = "openai"                    # любой OpenAI-совместимый Chat Completions
url = "http://host.docker.internal:11434/v1"
model = "qwen2.5:14b"                  # локальной модели токен не нужен
```

- `provider = "anthropic"` — модели Claude.
- `provider = "openai"` — OpenAI, OpenRouter, DeepSeek, Mistral, Groq, Together,
  локальные Ollama, LM Studio и vLLM, шлюзы к YandexGPT и GigaChat с
  OpenAI-совместимым API.
- `token` — токен прямо в файле, или `token_env` — имя переменной окружения.
- Необязательно: `max_output_tokens` (4096), `timeout_seconds` (120),
  `temperature`, `headers = { "Имя" = "значение" }` — заголовки шлюза.

Файл перечитывается при каждом решении — правка применяется без перезапуска.
Раздел панели **«Модели ИИ»** показывает профили (токены — только «задан в файле»
или «из переменной …») и проверяет подключение кнопкой «Проверить». Из терминала:

```sh
tinkoff-bot ai-profiles                 # профили без токенов
tinkoff-bot ai-check --profile claude   # короткий запрос к модели
```

## Стратегия в портфеле

Модель работает с любыми инструментами блока: акциями, фондами, облигациями,
фьючерсами и валютой. Она видит тип каждого инструмента и то, что важно для
него: у фьючерса базовый актив, текущий контракт, стоимость пункта, ГО и дату
перехода на следующий контракт; у облигации номинал, погашение, купоны и НКД.
Мультипликаторы, дивиденды и прогнозы аналитиков есть только у акций. Перенос
непрерывного фьючерса в следующий контракт стенд делает сам.

Модель знает издержки сделок: в каждом решении ей передаются ставки комиссии
контура по типам инструментов и порог сделки, а в истории решений итог через 1, 5
и 20 дней указан после комиссии за перекладку (оборот × ставка). Так же считаются
рейтинг моделей и итоги в разборе.

ИИ-портфель переносится на реальный счёт так же, как остальные: «Реальные счета
→ Перевести портфель на реальный счёт». Порог для него — число решений модели в
песочнице (по умолчанию 5) вместо числа сделок; переносятся модель, профиль,
настройки и память.

В «Стратегии → Собрать портфель счёта» выберите для блока «ИИ-модель: новости и
индикаторы» и задайте:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| Модель (профиль) | `default` файла | `model_profile` — имя профиля |
| Идея стратегии | — | `instructions` — что учитывать и как торговать, своими словами |
| Доля одной бумаги, % | 25 | `max_weight_percent` |
| Новости за, ч | 24 | `news_hours`, до 168 |
| Разрешить short | нет | `allow_short`; без него модель держит только long |

В TOML доступны также `max_tool_rounds` (8, до 20) и `news_feeds` — ленты для
пробного анализа без базы стенда (на стенде документы собирает сборщик, см.
ниже). Пример — `examples/configs/ai-model.toml`.

## Документы

Отдельный процесс стенда — **сборщик документов** (`tinkoff-bot collect`) —
работает, пока включён хотя бы один портфель с ИИ-моделью, и складывает в
PostgreSQL:

| Источник | Что даёт | Как часто |
|---|---|---|
| Новости T-Invest | полные тексты Интерфакса, РИА Новостей и ТАСС, **раскрытие информации эмитентов** (существенные факты), отметки бумаг и важности | 2 мин |
| Деловые ленты (Коммерсантъ, Ведомости, Финам) | анонс из RSS и полный текст статьи со страницы | 5 мин |
| Мосбиржа | сообщения биржи: торги, риск-параметры, индексы, листинг | 5 мин |
| Банк России | пресс-релизы и события | 15 мин |
| Сайты эмитентов | пресс-релизы и отчётность (PDF) | 1 час |

- Полный текст статьи берётся только с открытых страниц и только если это
  разрешает `robots.txt` сайта; между запросами к одному сайту — пауза. Сайт,
  ответивший отказом (защита от ботов, платный доступ), шесть часов не
  запрашивается, а документ остаётся с анонсом из ленты. Так сейчас с Финамом.
- Одно событие из нескольких лент (перепечатка, Интерфакс в T-Invest и в RSS)
  склеивается в одно: модель видит его один раз со списком источников.
- Документ режется на фрагменты по ~1500 символов с подписью (заголовок,
  источник, дата) для полнотекстового поиска с русской морфологией.
- Настройки — файл `SOURCES_FILE` (в Compose `docker/local/ai/sources.toml`,
  пример — `examples/sources.example.toml`): ленты, частота, паузы, селекторы
  текста для сайтов, сроки хранения. Без файла действуют значения по умолчанию.
- Поиск по смыслу (векторы) включается разделом `[embeddings]` того же файла:
  локальная модель в службе `embeddings` или внешний сервис. Без него поиск
  только по словам — во всех падежах. С ним результаты поиска по словам и по
  смыслу объединяются: запрос «углеводороды» находит новость про НДПИ для
  нефтяников без общих слов. Если сервис векторов не ответил, поиск остаётся
  полнотекстовым (в журнале — предупреждение).
- С векторами одно событие от разных агентств склеивается и при разных
  заголовках: новый документ присоединяется к событию другого источника за
  ±12 часов, если первые фрагменты близки по смыслу не меньше
  `same_event_similarity` (0,92). Готовые события между собой не сливаются,
  чтобы соседние темы не собирались цепочкой в одно. У моделей семейства e5
  близость разных текстов на одну тему высока — поднимите порог до 0,95; `1`
  отключает склейку.

### Сайты эмитентов и цифры отчётности

Раздел `[issuers]` файла источников перечисляет сайты эмитентов: RSS пресс-релизов
или страницу списка с шаблоном пути ссылки на публикацию (ссылка на PDF —
отчётность, текст извлекается `pdftotext`). Первый обход сайта только запоминает
уже опубликованное; документами становятся новые публикации. По умолчанию
настроены Газпром и Роснефть (RSS), Северсталь, МТС и ММК (страницы). Сайты со
списком, который рисуется скриптами (Лукойл, Норникель, Новатэк), и с защитой от
ботов (Сбербанк) не обходятся: их события приходят через раскрытие информации в
новостях T-Invest и ленту Интерфакса.

Из документов, которые разметка признала отчётностью, прогнозом, дивидендами или
операционными данными (важность от 3), дешёвая модель вытаскивает **ключевые
цифры**: период и стандарт, выручку, EBITDA, прибыль, долг, денежный поток,
дивиденд, производство — с прошлым периодом и изменением, а также прогноз
компании. Модель торговли получает их инструментом `get_facts`; прогнозы
инвестдомов по цене — `get_analysts`.

### Разметка и непрямые связи

Новость может касаться бумаги, не называя её: «санкции против экспорта нефти»,
«ЦБ снизил ставку», «Brent подорожал». Чтобы модель видела такие связи:

1. **Разметка.** Сборщик отдаёт каждое новое событие (один документ на кластер)
   дешёвой модели — по умолчанию Claude Haiku 5.5 через ваш ключ Anthropic,
   раздел `[tagging]` файла источников. Она возвращает: относится ли документ к
   рынку, важность 1–5, вид события, краткое содержание, затронутых эмитентов и
   **темы со знаком и силой** — 25 тем: геополитика, санкции, нефть, газ, металлы,
   золото, уголь, удобрения, рубль, ключевая ставка, инфляция, бюджет, налоги,
   дивидендная политика, банки, спрос, недвижимость, технологии, связь,
   электроэнергетика, транспорт, Китай, мировые рынки, регулирование рынка,
   корпоративные события. Знак — куда событие двигает тему: для нефти +1 — рост
   цен, для санкций +1 — ослабление, для ставки +1 — повышение. Спорт, культура и
   погода отсекаются без модели. Около 1500 документов в сутки обходятся
   примерно в $0,1–0,2.
2. **Чувствительность бумаг.** Для каждой бумаги блока модель один раз пишет
   черновик профиля: отрасль, чем зарабатывает компания и чувствительность к темам
   от −2 до +2 (насколько бумаге хорошо, когда тема движется вверх). Например,
   ЛУКОЙЛ: нефть +2, рубль −1, санкции +1,5. Профили видны и правятся в «Модели ИИ
   → Чувствительность бумаг»; правки оператора модель не меняет.
3. **Влияние.** Знак темы × сила × чувствительность — ожидаемое влияние события на
   бумагу. В сводке перед решением у события видно «LKOH ↑ нефть, SBER ↓ санкции»,
   и такие события попадают в сводку, даже если бумаги в тексте нет.
4. **Проверка по факту.** Раз в сутки (перед первым решением дня) стенд меряет,
   как бумаги блока на самом деле реагировали на темы за 120 дней: в дни с
   размеченными событиями темы (важность от 3) сигнал — сумма «знак × сила»,
   реакция — доходность бумаги сверх индекса Мосбиржи, а для общерыночных тем
   (геополитика, санкции, ставка, инфляция, бюджет, мировые рынки) — доходность
   целиком. Событие после 18:40 МСК относится к следующему торговому дню. Если
   таких дней не меньше 8, наклон «реакция на единицу сигнала» с поправкой на
   малую выборку переводится в шкалу −2…+2. Измерение **ничего не меняет само**:
   модель видит его в `get_exposure` рядом с заданной чувствительностью, а в
   таблице «Чувствительность бумаг» клетка с заметным расхождением помечена «≈»
   и измеренным значением — его можно подставить в форме правки. Измерение
   грубое (события одной темы часто совпадают с другими), поэтому решение
   остаётся за оператором.
5. **Состояние рынка.** Перед решением модель видит индекс Мосбиржи, индекс
   гособлигаций, нефть Brent (ближайший фьючерс), юань, доллар, золото и ключевую
   ставку — изменения с открытия, за день, 5 и 20 дней. Так видно, как рынок уже
   отреагировал на события.

Документы видны в разделе дашборда **«Документы»**: состояние каждого источника,
лента с поиском по словам, виду, источнику, тикеру и периоду, полный текст и
другие источники того же события. Из терминала:

```sh
tinkoff-bot documents --query "дивиденды" --ticker SBER --hours 168
```

## Когда модель принимает решение

- **На открытии сессии** и **по расписанию**: по умолчанию каждый час
  (`decision_interval_minutes`: 15, 30, 60, 120, 240 или 0 — только открытие).
- **Внеочередно** в основную сессию — стенд раз в минуту смотрит цены и раз в
  5 минут новые документы:
  - всплеск событий: не меньше `news_burst_items` (3) событий о бумагах блока
    за `news_burst_minutes` (30) минут с прошлого решения (повторы агентств —
    одно событие);
  - скачок цены: на `price_jump_percent` (2%) с прошлого решения или на
    `fast_jump_percent` (1%) за 10 минут;
  - **важное событие эмитента**: событие о бумаге блока с важностью разметки не
    ниже `material_importance` (4: отчётность, дивиденды, крупная сделка, решение
    регулятора); пауза после прошлого решения — всего 10 минут, каждое событие —
    один раз;
  - **условие тезиса**: цена бумаги дошла до уровня из тезиса или наступила
    его дата; каждое условие — один раз;
  - **резкое движение рынка** с открытия: индекс Мосбиржи на `market_move_percent`
    (2%), нефть Brent на `commodity_move_percent` (3%), юань или доллар на
    `currency_move_percent` (1,5%). Каждый следующий уровень (двойной, тройной)
    спрашивает модель ещё раз за день. 0 выключает повод.

  Внеочередное решение исполняется сразу. Между ними — не меньше
  `min_minutes_between_decisions` (20) минут, всего за день не больше
  `max_decisions_per_day` (24) обращений к модели.
- Решение может быть любым: купить, продать, сократить, увеличить или **держать**
  (`hold`) — тогда сделок нет.

## Память модели

- **История документов.** Сборщик хранит новости и статьи год, раскрытие
  информации и сообщения регулятора — бессрочно; модель ищет по всей истории.
- **История котировок.** Дневные свечи — до 250 дней, часовые — до 250 часов,
  индикаторы — по любым из них.
- **Прошлые решения.** В каждый разговор подаются последние пять решений с
  обоснованием; больше — инструмент `get_decisions`.
- **Тезисы** (`memory = true` по умолчанию). Каждую идею по бумаге модель
  оформляет тезисом (`open_thesis`): направление (покупка, продажа, избегать),
  обоснование, горизонт, документы-основания и **условия выхода** — уровни цены
  и дату. Цена открытия запоминается; модель уточняет тезис (`update_thesis`) и
  закрывает его (`close_thesis`) — тогда считается результат с учётом
  направления. Когда условие наступает (цена дошла до уровня, пришла дата),
  стенд спрашивает модель внеочередно. Открытые тезисы с текущей ценой и
  результатом видны модели в каждом решении, вам — в блоке «Тезисы».
- **Заметки** — наблюдения и планы без привязки к сделке (`remember`/`forget`),
  до 50 активных.
- **Итоги решений.** Перед первым решением дня стенд считает, как сработало
  каждое прошлое решение: доходность его целевых долей и индекса Мосбиржи через
  1, 5 и 20 торговых дней («держать» — по долям предыдущего решения). Итоги видны
  модели в истории решений и сводкой («из 12 решений лучше индекса 7, в среднем
  +0,4 п.п.»), вам — в карточке решения.
- **Разбор раз в неделю.** Перед первым решением недели, если есть закрытые
  тезисы или итоги, модель разбирает их и записывает **выводы** (до 20 активных:
  что работало, какие поводы были ложными); устаревшие выводы закрывает. Выводы
  видны ей во всех решениях. Когда заметок больше 40, старые 20 сжимаются в
  сводки. Разбор входит в дневной лимит расходов.
- **Перенос памяти.** Новая версия портфеля после смены состава и копия на
  реальном счёте получают активные заметки, выводы и открытые тезисы
  предшественника (в панели — с пометкой «перенесено») и видят его решения с
  итогами до момента переноса.
- **Пробный анализ** читает память, но не меняет её.

## Как модель принимает решение

1. Стенд передаёт модели причину решения, бумаги блока, текущий портфель, память,
   последние решения, **сводку событий** с прошлого решения (о бумагах блока и
   важные: раскрытие эмитентов, сообщения регулятора, события из трёх и более
   источников; повторы агентств склеены) и **календарь** отчётности и
   дивидендов на 14 дней. Если сборщик отстаёт, модель получает предупреждение.
2. Модель вызывает инструменты сколько нужно (не больше `max_tool_rounds`):
   - `search_documents` — поиск по документам за неделю по умолчанию и до года:
     слова в любом падеже, тикеры (подставляются названия компаний — «Норникель»,
     «Сбер»), вид документа; результат — события со списком источников и
     фрагментом текста;
   - `read_document` — полный текст по страницам, таблицы, другие источники;
   - `get_calendar` — даты отчётности и дивидендов;
   - `get_analysts` — консенсус-прогноз и последние прогнозы инвестдомов;
   - `get_market_context` — состояние рынка (см. выше);
   - `get_exposure` — чувствительность бумаг блока к темам и измеренная
     реакция на них;
   - `get_facts` — цифры последней отчётности и прогнозов эмитентов;
   - у `search_documents` есть фильтры по темам и важности разметки;
   - `get_candles` — дневные свечи до 250 дней и часовые до 250 часов;
   - `get_indicators` — `price`, `sma_N`, `ema_N`, `rsi_N`, `macd`, `bollinger_N`,
     `atr_N`, `volatility_N`, `return_Nd`, `high_52w`, `low_52w`,
     `distance_from_high_52w`, `volume_avg_N`, `max_drawdown_N`;
   - `get_fundamentals` — P/B, P/E, EV/EBITDA, ROE, ROA, маржа, долг и дивиденды;
   - `get_portfolio` — текущие доли блока;
   - веб-поиск провайдера, если включён `web_search`.
3. Решение — вызов `submit_decision`: доли бумаг в процентах, обоснование и id
   документов-оснований. В журнале решения видны все документы, которые
   модель видела, основания — первыми.

Затем стратегия применяет лимиты: инструменты вне блока отбрасываются, доля
бумаги — не больше `max_weight_percent`, без `allow_short` отрицательные веса
обнуляются, сумма модулей — не больше 100%. Дальше работают обычные бюджет,
стопы, планировщик заявок и, на реальном счёте, подтверждение каждого плана.

Тексты документов передаются модели как данные: системная инструкция запрещает
выполнять просьбы и команды из них, а инструменты модели только читают.

## Надёжность и стоимость

- Модель опрашивается один раз на каждый пересмотр; повтор после пропущенного
  открытия использует уже полученное решение.
- Сбой модели или сети повторяется через минуту, не больше трёх попыток на
  пересмотр; потом блок сохраняет позиции до следующего пересмотра.
- Решение одной модели ограничено 10 минутами; пока модель думает, процесс
  стратегии ждёт её ответа.
- Стоимость — один диалог с несколькими вызовами инструментов на решение:
  около 10 плановых решений в день при пересмотре раз в час плюс внеочередные;
  всего не больше `max_decisions_per_day`. Число вызовов инструментов в одном
  решении ограничивает `max_tool_rounds`.

## Расходы и дневной лимит

- **Учёт.** Каждый запрос к модели записывает токены (вход, выход, кэш) и
  платные веб-поиски в таблицу `ai_usage`; у решения в панели видны число
  запросов, токены и цена, в разделе «Модели ИИ» — расход за сегодня и за 7 дней
  по видам работы. Всё в рублях: цены в долларах пересчитываются по курсу
  доллара Мосбиржи (USD000UTSTOM), который наблюдатель берёт из T-Invest раз в
  6 часов; без курса расход оценивается по 100 ₽ за доллар.
- **Цены.** Для моделей Anthropic (Sonnet 4.6 и 5.5, Opus 5.5, Haiku 4.5 и 5.5)
  цены встроены (октябрь 2026). Для других моделей или своих цен задайте их в
  профиле, иначе расход не оценивается:

  ```toml
  [models.my]
  prices = { input = 3, output = 15, cache_write = 3.75, cache_read = 0.3, web_search_per_1000 = 10 }
  ```

  Цены — за миллион токенов, веб-поиск — за тысячу запросов; валюта — доллары,
  для цен в рублях (например, Cloud.ru) — `currency = "rub"` в `prices`.
- **Дневной лимит** — общий на все модели, в рублях, по московским суткам:
  «Модели ИИ → Расходы на запросы к моделям», по умолчанию 500 ₽. Раздел
  `[budget]` файла профилей больше не действует (панель подскажет его убрать).

  Когда лимит исчерпан, **внеочередные** решения (всплеск новостей, скачок цены),
  разметка документов, разборы и профили бумаг ждут следующих суток — в журнале
  решений это видно с причиной.
  Плановые решения (открытие и пересмотры по расписанию) продолжаются, поэтому
  лимит может быть превышен на их стоимость.
- **Кэш промпта.** Для Anthropic системный промпт, описания инструментов и
  диалог помечаются для кэша: повторные шаги одного решения читают их из кэша
  в 10 раз дешевле. Отключение — `prompt_cache = false` в профиле.

## Решения модели

На странице стратегии блок **«Решения модели»** показывает каждое решение,
пробный анализ и ошибку: модель, доли бумаг, обоснование, прочитанные новости со
ссылками и вызванные инструменты. Кнопка **«Пробный анализ»** спрашивает модель
прямо сейчас и показывает решение без заявок. Из терминала:

```sh
tinkoff-bot --config bot.toml ai-preview
```

Журнал хранится в таблице `ai_decisions` PostgreSQL.
